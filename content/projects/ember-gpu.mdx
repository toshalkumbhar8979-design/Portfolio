## Project Overview

A complete GPU system-on-chip designed from scratch in SystemVerilog. It combines a graphics rasterizer, vector floating-point unit, tensor accelerator, and multithreaded compute core on a self-built AMBA AXI4-Lite fabric, with 512 KB of unified memory and a DMA command processor.

![EMBER GPU architecture diagram](/projects/ember-gpu/architecture.png)

## SoC Architecture

* **Rasterizer:** A PS1-era graphics pipeline implemented as a multi-cycle FSM, including Z-buffering, CLUT textures, alpha blending, and dithering.
* **Vector FPU:** A four-lane IEEE-754 fp32 unit supporting round-to-nearest-even, subnormals, and NaN handling.
* **Tensor unit:** A 16×16 int8 systolic array using TPU-v1-style weight-stationary dataflow.
* **Compute core:** A four-thread core with a custom 32-bit ISA and a self-written assembler.
* **System integration:** A self-built AMBA AXI4-Lite fabric connects the blocks to 512 KB unified memory and a DMA command processor.

## Verification & Demonstrations

* **RTL regression:** 31/31 cocotb tests pass bit-exactly against independent Python golden models. Modelling truncation and rounding independently caught a tensor-unit row-counter width bug: eight bits could not represent the 688 rows required by a convolution.
* **Floating point:** The FPU passed 6,720 comparisons with zero mismatches.
* **CNN inference:** A trained LeNet reached 98% accuracy across 100 MNIST samples through the RTL data path, byte-for-byte matching the software mirror.
* **Game loop:** A 112-instruction Q16.16 physics kernel runs on the compute core and matches the Python mirror over all 32 demo frames. The final host-rendered frame matches the testbench on all 10,316 pixels.
* **Scene-level checks:** Renderer tests assert meaningful scene properties—including at least 12 colors, 20,000 non-background pixels, 50 distinct depth values, and frame-to-frame change—and reject degenerate golden output.

## ASIC Implementation

Tcl scripts drive the OpenROAD floorplan, placement, clock-tree synthesis, and global/detailed routing flow with SDC clock constraints. Across 11 blocks, 2,266,911 standard cells were mapped on the SkyWater sky130 process using Yosys, OpenROAD, Magic, and KLayout. Independently audited block layouts have zero DRC violations and timing met with non-negative STA slack.

The core block's physical run is still in progress; this is not a claim of whole-chip tapeout or sign-off. The verified results are bit-exact RTL, multiple zero-DRC blocks, and timing-met routed blocks.

## Performance & Design Decisions

At 100 MHz, the tensor unit sustains 1.57 GOPS against a 51.2 GOPS array peak (about 3% utilization). Profiling traced the gap to a streaming-bound address controller that does not double-buffer operands; an operand-double-buffered streaming controller is the identified next optimization, not a performance result claimed here. The worst demo frame takes about 615,000 cycles: 6.15 ms at 100 MHz or 12.3 ms at 50 MHz.

The SoC deliberately uses one clock domain, eliminating CDC crossings from this design. Multi-clock synchronization techniques such as two-flop synchronizers, Gray-coded pointers, and handshakes are understood as concepts but were not needed in this single-domain implementation.

## Verification Methods & Skills

* **Hands-on:** SystemVerilog/Verilog RTL, multi-cycle FSM and FIFO datapaths, self-built AMBA AXI4-Lite fabric, independent cocotb scoreboards, Python golden models, and a Verilator lint gate (one documented waiver).
* **Physical design:** Tcl scripting, SDC constraints, STA slack review, Yosys, OpenROAD, OpenLane 2, Magic, and KLayout.
* **Additional languages and tools:** Python, C++, embedded C, MATLAB, Vivado, and cocotb.
* **Qualified familiarity:** UVM methodology and SVA concepts; verification was implemented with cocotb rather than UVM, and assertions/coverage closure are not claimed as completed project work.
